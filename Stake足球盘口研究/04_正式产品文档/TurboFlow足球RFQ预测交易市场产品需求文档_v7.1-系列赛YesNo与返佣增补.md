# TurboFlow 足球 RFQ 预测交易市场产品需求文档 v7.1 增补：系列赛 YES/NO 全覆盖与返佣

版本：v7.1（增补）
基准文档：`TurboFlow足球RFQ预测交易市场产品需求文档_v7.0.md`
状态：当前评审稿

## 1. 增补目标

v7.1 修正系列赛预测的二元命题表达：所有可表达为“候选 X 是否达成结果 Y”的系列赛 / 赛季市场，都必须提供 YES 与 NO 两侧交易。

本增补不改变单场预测 7/7 的产品形态。单场仍沿用 v7.0 RFQ 交易逻辑。

## 2. 正确模型

每个候选结果是一条二元子市场：

```text
候选 X 是否达成结果 Y
  YES：候选达成该结果
  NO：候选未达成该结果
```

示例：

```text
进入8强
法国        [ 是 ] [ 否 ]
巴西        [ 是 ] [ 否 ]
```

用户买入“法国 是”表示押法国进入 8 强；用户买入“法国 否”表示押法国不进入 8 强。

禁止把“法国 是”和“法国 否”拆成两张普通卡片，再在卡片内显示 `Buy Yes`。这种表达会变成“买入法国否这个 outcome 的 YES”，不符合用户心智。

## 3. 全局系列赛市场模型

v7.1 必须同时满足两层概率口径：

1. 候选内互补：同一候选的 YES 与 NO 互补，`候选 YES + 候选 NO ≈ 1`。
2. 市场组约束：同一市场组内所有候选的 YES 不是完全无约束独立，而是按该市场最终可成立名额数形成分布。

Polymarket 的冠军市场属于唯一结果型：所有候选都在同一个“谁会夺冠”市场组内，法国、西班牙、英格兰、巴西等候选的 YES 共同组成冠军概率分布，合计应约等于 100%。每个候选仍有自己的 NO，但 NO 是该候选的反面，不等于另一个候选的 YES。

| 市场 | 模型 | 目标名额 | 候选覆盖口径 | 展示要求 |
|------|------|----------|--------------|----------|
| 小组第一 | 唯一结果型 | 1 | 小组全量候选；若只列主要队伍，必须有“其他球队”合计 | YES 合计目标约 100% |
| 小组出线 | 多名额型 | 小组出线名额，例如 2 | 小组全量候选；若只列主要队伍，必须有“其他球队”合计 | YES 合计目标约 200% |
| 进入 8 强 | 多名额型 | 8 | 可展示热门候选，但必须标注“当前展示候选合计” | 不得把热门候选合计误写成全量 800% |
| 进入 4 强 / 半决赛 | 多名额型 | 4 | 可展示热门候选，但必须标注“当前展示候选合计” | 不得把热门候选合计误写成全量 400% |
| 进入决赛 | 多名额型 | 2 | 可展示热门候选，但必须标注“当前展示候选合计” | 不得把热门候选合计误写成全量 200% |
| 冠军 | 唯一结果型 | 1 | 全量候选，或热门候选 + “其他球队”合计 | YES 合计目标约 100% |
| 两回合晋级 | 唯一结果型 | 1 | 两队全量候选 | 两队 YES 合计目标约 100% |
| 欧冠资格 | 多名额型 | 赛季规则名额 | 可展示竞争候选，但必须标注“当前展示候选合计” | 不得把竞争候选合计误写成全量名额 |
| 降级 | 多名额型 | 降级名额，例如 3 | 可展示高风险候选，但必须标注“当前展示候选合计” | 不得把高风险候选合计误写成全量降级名额 |

RFQ / SIG 口径下，前端不做撮合、不强行制造套利，也不机械调整成交价格；前端只展示市场组目标、YES 合计或参考校验。真正成交仍以交易面板最新报价为准。

候选覆盖范围必须在 mock 和设计稿里显式表达：

- `全量候选`：页面列出了该市场所有可能候选。
- `热门候选 + 其他候选合计`：页面列出主要候选，并用“其他球队 / 其他候选”承接剩余概率。
- `当前展示候选`：页面只展示部分热门或高风险候选，YES 合计只能叫“已展示 YES 合计”，不能叫“全组合计”。

## 4. 覆盖范围

| 类型 | 命题 | 是否必须 YES/NO |
|------|------|-----------------|
| 小组第一 | 墨西哥是否获得 A 组第一 | 是 |
| 小组出线 | 墨西哥是否从 A 组出线 | 是 |
| 进入 8 强 | 法国是否进入 8 强 | 是 |
| 进入 4 强 / 半决赛 | 法国是否进入 4 强 | 是 |
| 进入决赛 | 法国是否进入决赛 | 是 |
| 冠军 | 法国是否获得冠军 | 是 |
| 两回合晋级 | 皇家马德里是否晋级 | 是 |
| 欧冠资格 | 纽卡斯尔是否获得欧冠资格 | 是 |
| 降级 | 伯恩利是否降级 | 是 |

只要后续新增系列赛命题符合“候选 X 是否达成结果 Y”，默认也按本规则处理。

## 5. 互补、互斥与相关性

同一候选内：

- YES 与 NO 在结算上互补。
- 候选达成结果时，YES 兑付，NO 失败。
- 候选未达成结果时，NO 兑付，YES 失败。
- void 时，YES 与 NO 均按 void 退款规则处理。

不同候选之间：

- 多候选在赛事事实层可能互斥、强相关或受名额数约束。
- 合约层按候选独立持仓、独立成交、独立结算，但同一市场组的 YES 概率展示必须受市场组名额约束。
- “法国 NO”不等于“巴西 YES”。

## 6. UI 与交互要求

系列赛详情页必须按候选行展示：

```text
A组出线
墨西哥      [ 是 75.8¢ ] [ 否 29.4¢ ]
捷克        [ 是 47.6¢ ] [ 否 58.1¢ ]
```

交易面板：

- 点击“是”后，面板显示当前选择为 YES 腿。
- 点击“否”后，面板显示当前选择为 NO 腿。
- NO 腿价格文案必须是 `Buy No` 或中文等价表达，不得显示 `Buy Yes`。
- 修改候选、修改 YES/NO、修改金额都会使旧报价失效。

市场卡片：

- 唯一结果型市场应展示“YES 合计约 100%”或等价文案。
- 多名额型市场应展示“YES 合计目标 = 名额数”，例如小组出线目标为 2、进入决赛目标为 2。
- 如果当前 mock 只展示部分候选，必须标明这是“已展示候选合计”，避免误读为完整市场分布。

Portfolio：

- 按 `(赛事 / 市场 / 候选)` 分组。
- 组内 YES 与 NO 分行展示。
- YES 行只能卖 YES，NO 行只能卖 NO。
- 不展示合并均价或净持仓。

## 7. 报价要求

页面展示价仍是参考价，成交以交易面板最新报价为准。

当 NO 侧价格由 YES 隐含概率互补推导时，前端必须标注：

```text
参考价（成交以最新报价为准）
```

上线后如果报价源直接提供 NO 侧可成交报价，则可以去掉参考价标识，但仍必须保留 YES/NO 双侧结构。

## 8. 结算要求

| 事实结果 | YES | NO |
|----------|-----|----|
| 候选达成命题 | 兑付 1 USDT / 份 | 兑付 0 |
| 候选未达成命题 | 兑付 0 | 兑付 1 USDT / 份 |
| void | 按 void 退款 | 按 void 退款 |

结算来源继续沿用 v7.0：官方赛事结果为最终权威，provider settlement feed 只能作为自动化输入，不得覆盖官方结果。

## 9. 返佣逻辑

足球 RFQ 的所有成交量计入主站返佣。

返佣逻辑沿用主站已有实现：

- 直推线：用户直接邀请关系产生的成交量计入直推返佣。
- 代理线：代理关系按主站现有无限级代理规则计入。
- 足球 RFQ 不单独重画返佣展示组件。
- 如果主站当前对用户展示返佣，足球 RFQ 成交应进入同一展示口径。
- 如果主站当前不对用户端暴露返佣，足球 RFQ 也不额外暴露。

本增补只定义产品口径，不展开主站返佣事件命名、归因配置和结算周期。

## 10. 验收清单

- 冠军市场显示每个候选的 YES/NO。
- 冠军、小组第一、两回合晋级等唯一结果型市场的候选 YES 合计约等于 100%。
- 小组出线、进入8强、进入4强、进入决赛、欧冠资格、降级等多名额型市场展示名额数目标。
- 小组第一显示每个候选的 YES/NO。
- 小组出线显示每个候选的 YES/NO。
- 进入8强、进入4强、进入决赛显示每个候选的 YES/NO。
- 两回合晋级、欧冠资格、降级显示每个候选的 YES/NO。
- 不出现“法国 否”普通卡片内 `Buy Yes` 的表达。
- 交易面板能区分 YES 腿和 NO 腿。
- Portfolio 按候选分组，YES/NO 分行。
- 单场 7/7 不变。
- 足球 RFQ 成交量进入主站返佣口径。
