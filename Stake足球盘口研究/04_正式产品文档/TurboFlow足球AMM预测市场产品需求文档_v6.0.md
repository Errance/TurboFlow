# TurboFlow 足球 AMM 预测市场产品需求文档 v6.0

## 版本定位

v6.0 是足球 tab 的主线升级版本，用 AMM 预测市场替代 v5.0 的平台报价型传统盘口。v5.0 保留为历史基线；本文件是完整 PRD，不是增量说明。

本期只改当前足球 tab 对应的 `/soccer` mock 和足球产品文档。现有市场目录、入口、分组和数量保持不变：单场预测仍覆盖当前 7 个核心市场，冠军与晋级仍覆盖当前 11 个赛事级市场。不新增球员、角球、罚牌、分钟盘、组合盘，不改 `/clob`，不扩张到非足球 tab。

## 核心原则

平台不做用户交易对手方，不承诺赔率，不用传统注单结算用户输赢。平台提供市场创建、AMM 交易、信息展示、风控、结算和协议收费能力；流动性由外部做市商 / 流动性提供方提供。外部流动性方在 PRD 中只作为抽象待定契约，不嵌入具体供应商名称。

v6.0 是 AMM 即时交易，不是 CLOB。当前版本不做订单簿、限价单、挂单、撤单、订单深度和部分成交挂起。用户买入和卖出都通过 AMM 即时报价完成；报价过期、流动性不足、价格影响超过保护阈值或市场暂停时，整笔交易失败并要求重新询价。

## 市场范围

单场预测保留当前 7 个核心市场：胜平负、开球权、让球、让球 0:1、总进球数、大小球、波胆。每个市场内原有可选结果转换为可交易 outcome。

冠军与晋级保留当前 11 个赛事级市场：世界杯 A 组第一、世界杯 A 组出线、进入 8 强、进入决赛、世界杯冠军、欧冠冠军、晋级决赛、两回合系列赛赛果、英超冠军、获得欧冠资格、降级球队。系列赛 / 赛季对象组织方式不变。

每个 market 必须包含：`question_title`、`outcomes`、`resolution_rule`、`resolution_source`、`expected_resolution_time`、`void_rule`、`delay_or_dispute_policy`。足球场景中的 VAR、延期、腰斩、官方改判、小组排名规则和资格递补必须能被这些字段解释。

## 交易模型

用户买入某个 outcome 的预测份额，形成 position。position 记录剩余份额、平均成本、当前价格、持仓市值、已实现盈亏和未实现盈亏。

用户可以继续买入、部分卖出、全部卖出或等待结算。部分卖出定义为：用户输入小于或等于当前可用持仓的 shares，系统返回即时卖出 quote，用户确认后完整成交该数量。部分卖出不是部分成交；不引入订单等待、撤单或挂单状态。

卖出后如果剩余持仓价值低于 `dust_threshold`，前端提示改为全部卖出，或由产品规则归并为全仓卖出。

结算时正确 outcome 每份兑付 1 USDT，错误 outcome 兑付 0。市场 void 时按规则退回可兑付价值。

## AMM 定价与流动性

系统主价格是概率 + 份额价格的组合展示，例如 `55%` + `Buy Yes 55¢` 或 `$0.55 / share`。欧洲赔率是展示换算，公式为 `decimal_odds = 1 / probability`。切换价格格式只影响展示，不改变交易请求、quote 计算和结算字段。

价格格式入口使用小齿轮按钮。点击后打开弹框，在“概率 + 份额价格”和“欧洲赔率”之间切换。默认展示为“概率 + 份额价格”；欧洲赔率只作为辅助展示，不作为成交承诺。

市场 / outcome 卡片的信息密度必须受控。卡片主区域展示 outcome 名称、当前概率、Buy Yes / Buy No 份额价格。卡片辅助指标只展示：

- `24h Vol.`：用于表达该 outcome 或市场最近 24 小时交易活跃度。
- `24h 涨跌幅`：用于表达概率价格相对 24 小时前的变化。

卡片辅助指标不展示：流动性、implied probability、可交易文案、做市商状态、内部 quote 状态。开放、暂停、关闭、已结算、void 等状态通过卡片可点击 / 禁用、透明度、状态色、暂停提示等视觉状态表达。流动性不足、价格影响和 quote 过期属于交易执行反馈，应放在交易面板和异常提示中。

交易前 quote 必须展示：交易方向、outcome、份额、预估成交均价、交易后价格、价格影响、手续费、最大亏损、报价过期时间。卖出 quote 还必须展示预计收回金额、本次已实现盈亏、卖出后剩余份额和剩余持仓市值。

交易面板金额输入必须提供快速下单能力：

- 输入框尾部提供 `Max`，买入时填入当前可用余额或当前产品定义的最大可用金额；卖出时填入该 position 的全部可卖份额。
- 输入框下方提供固定快捷金额按钮：`50`、`100`、`200`、`500`。
- 快捷金额用于买入金额；卖出份额优先使用 `Max` / 全部卖出，避免把金额快捷按钮误解为份额快捷按钮。

AMM 定价来源仍为待确认事项，开发前必须在技术方案中选择并写清楚：纯 AMM 曲线定价、外部做市商报价驱动，或外部报价作为 AMM 参数输入。无论采用哪种实现，用户侧都只看到 AMM 即时交易，不看到供应商或 CLOB 订单簿。

外部流动性方契约待技术与供应商确认：报价刷新频率、最小可交易深度、最大价差、最大价格影响、单笔最大交易量、关键事件暂停条件、恢复条件、异常报价处理、回滚规则、流动性撤出限制、手续费与收益分配、`market_max_exposure`、`outcome_max_exposure`、`inventory_balance`、`rebalance_threshold`、`provider_quote_status`。

## 页面结构

`/soccer` 保留单场预测 / 冠军与晋级两个入口。首页展示 AMM 市场发现、价格格式切换、`24h Vol.`、`More` 入口和市场数量，不再使用“按比赛逐场下注”的文案。

`/soccer/match/:matchId` 展示比赛信息、原有市场 tab、AMM outcome 卡、价格格式切换、AMM 交易面板和 Portfolio 摘要。单场 7 个市场必须全部 AMM 化，不能只改胜平负示例。

`/soccer/futures/:competitionId` 展示系列赛 / 赛季对象、阶段分组、当前 11 个赛事级市场的 AMM outcome、交易面板和 Portfolio 摘要。长期市场同样使用买入、部分卖出、全部卖出和 position 生命周期表达。

`/soccer/mybets` 升级为 Portfolio / 我的持仓，展示当前持仓、可卖份额、平均成本、当前价格、持仓市值、未实现盈亏、已实现盈亏、历史成交和卖出入口。

`/soccer/design-board` 保留两个页内 tab：

- `v6.0 完整 Design Board`：展示当前足球 AMM 主流程的完整 UI、页面、状态和市场覆盖。
- `v5.0 → v6.0 UI 变更对比`：只展示用户可见 UI 的旧态 / 新态 / 变化点，不展示代码路径、store、PRD 引用、git 命令、scope、技术实现细节或未来 CLOB 边界。

Design Board 必须显式证明页面 5/5、单场市场 7/7、赛事级市场 11/11、状态和移除项均已覆盖。移除项也必须以 UI 方式展示，例如传统投注单消失、Cash Out 被卖出入口替代、串关入口不进入 v6 主流程。

## 接口改造方向

现有下单域接口不能作为 v6.0 主接口。交易域需要以下能力：

- `quote`：交易前询价，返回成交均价、价格影响、手续费、交易后价格和过期时间。
- `trade`：执行买入、部分卖出和全部卖出。
- `positions`：查询持仓、可卖份额、平均成本和盈亏。
- `trades`：查询成交历史。
- `portfolio`：聚合返回持仓、已实现 / 未实现盈亏、历史成交和已结算记录。
- `market_liquidity`：查询池状态、深度、外部流动性状态和暂停原因。
- `settlement`：市场结算和持仓兑付。
- `price_preference`：读取和更新用户价格显示偏好。

核心字段从 `order_type`、`decimal_odds`、`legs`、`stake` 改为 `side`、`outcome_id`、`shares`、`collateral_amount`、`avg_price`、`price_impact`、`fee`、`position_id`、`sell_mode`、`max_slippage`、`min_shares_out`、`min_collateral_out`、`quote_expires_at`。

## 风控与异常

关键事件期间必须支持暂停买入和卖出：进球、红牌、点球、VAR、重大伤停、官方公告、临近结算、数据源延迟、外部流动性异常、价格偏离过大。

暂停后恢复交易必须重新 quote，不沿用旧报价。异常报价、流动性不足、价格影响超阈值、报价过期都应给出明确可操作反馈。

多 outcome 市场必须定义总概率、归一化、结算互斥、库存风险、单 outcome 最大负债和流动性分配方式。不能因为多 outcome 风险高而保留传统投注分支。

## 验收标准

用户可以在单场预测和冠军与晋级中选择 outcome 并买入预测份额。

盘口卡片默认展示概率 + 份额价格，并且只展示 `24h Vol.` 和 24h 涨跌幅作为辅助指标；不展示流动性、implied、可交易文本或内部状态字段。

交易面板在买入金额输入框内提供 `Max`，输入框下方提供 `50 / 100 / 200 / 500` 快捷金额；卖出侧提供 `Max` / 全部卖出能力。

用户可以在 Portfolio 中看到持仓、可卖份额、平均成本、当前价格、市值、未实现盈亏、已实现盈亏和历史成交。

用户可以部分卖出和全部卖出；卖出 quote 展示收回金额、本次已实现盈亏、剩余份额和 dust 提示。

概率 + 份额价格 / 欧洲赔率切换影响首页、市场卡、交易面板和 Portfolio。交易确认信息中同时展示概率、份额价格和欧洲赔率，且文案明确欧洲赔率仅为展示换算。

当前足球 tab 可见的单场预测和冠军与晋级市场均按 AMM 持仓交易模型展示，不保留传统投注单、串关、平台赔率承诺、Cash Out 或注单结算主流程。

GitHub Pages 直接访问 `/TurboFlow/soccer/design-board` 必须通过 SPA fallback 正常进入应用，不应出现用户无法进入页面的 404 体验。
