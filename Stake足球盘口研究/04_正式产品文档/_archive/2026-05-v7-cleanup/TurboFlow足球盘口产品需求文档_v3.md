## 第 1 章：文档概述

### 1.1 文档目的

本文档是 TurboFlow 足球预测市场的完整产品需求定义。覆盖 **11 个 Tab、约 100+ 个盘口**的全量定义，包括每个盘口的含义、逻辑、胜负判定、时间口径和数据关联，同时定义页面结构、UI 组件、字段配置、状态矩阵、结算规则和边界条件。

### 1.2 术语表

| 术语 | 说明 |
|------|------|
| **1x2** | 最基础的赛果投注，三个选项：主胜(1)、平局(X)、客胜(2)。例如主队 2:1 赢了 → 选"1"的人赢 |
| **Double Chance（双胜彩）** | 将 1x2 的三个结果两两合并，只要命中其中之一即赢。例如选"主队或平局" → 只要客队不赢就算赢，风险更低但赔率也更低 |
| **Asian Handicap（亚洲让分盘）** | 强队虚拟"让"弱队若干球后再比较结果，只有赢/输两种结果，不存在平局。例如主队让 1.5 球，实际比分 2:0 → 让球后算 0.5:0，主队仍赢；实际比分 1:0 → 让球后算 -0.5:0，主队输。让球线可以是半球(0.5)、四分之一球(0.25)或整数(0, 1) |
| **O/U（Over/Under，大小球）** | 预测总进球数是否超过某个数值线。例如"大 2.5"= 预测两队合计进球 ≥ 3 个；"小 2.5"= 预测合计 ≤ 2 个。2.5 这个数值叫"盘口线(line)" |
| **BTTS（Both Teams To Score）** | 两队是否都会进球。选"是"= 预测双方各至少进 1 球；选"否"= 预测至少有一队 0 球 |
| **SGM / Bet Builder（同场赛复式投注）** | 同一场比赛中多个投注选项组合为一注，赔率相乘。例如同时选"主胜 + 大 2.5 + 球员A进球"，三项全中才赢，赔率 = 三项赔率的乘积 |
| **void（作废）** | 投注无效，本金原路退还。例如平局返还盘口中实际打平 → 投注 void，退还全部本金 |
| **push（推平）** | 亚盘或大小球中的特殊情况：投注额原路退还。例如大小球线为 2，总进球恰好 2 个 → push，退款。只在整数线上可能出现 |
| **settled（已结算）** | 市场已有明确结果，所有投注已按结果派奖或扣除 |
| **odds（赔率）** | 也叫倍率，使用欧洲小数格式。赔率 × 投注金额 = 赢时的返还总额（含本金）。例如赔率 2.50，投入 100 → 赢了返还 250（净赚 150）；输了损失 100 |
| **line（盘口线）** | 大小球或让球的具体数值。例如 O/U 2.5 中的"2.5"、亚洲让分盘 -0.75 中的"-0.75"都是 line |
| **runner（参赛球员）** | 在进球者市场中，指开球后或上一粒进球之后实际上过场的球员。未上场球员的投注按 void 处理 |
| **常规时间（Regular Time）** | 法定 90 分钟 + 伤停补时。不含加时赛和点球大战。本文档中绝大多数盘口都按常规时间结算 |
| **suspended（暂停）** | 盘口临时关闭投注（通常在赛中进球、红牌等关键事件时），待赔率调整后重新开放 |

## 第 2 章：产品概述

### 2.1 产品定位

TurboFlow 足球预测市场为用户提供单场足球比赛的全量盘口投注体验，覆盖赛前、赛中、赛后三种比赛状态：

- **赛前 (scheduled)**：完整盘口投注 + 开赛倒计时 + 阵容排布图 + 历史交锋(H2H)记录
- **赛中 (live)**：实时比分 + 事件时间线 + 统计数据对比 + 滚球盘口（部分盘口可暂停）
- **赛后 (finished)**：最终比分 + 完整事件回顾 + 统计对比 + 盘口结算结果展示

### 2.2 覆盖范围

| 维度 | 范围 |
|------|------|
| Tab 数量 | 11 个 |
| 盘口总数 | 约 100+ 个独立盘口定义 |
| 市场 UI 类型 | 6 种 |
| 比赛状态 | scheduled / live / finished 三种基础状态 + interrupted / abandoned / postponed / cancelled / corrected 五种异常状态 |
| 球员数据 | 每场动态生成（派生自两队阵容首发 + 替补，通常约 34-36 名） |

## 第 3 章：产品信息架构与页面结构

### 3.1 页面层级

```
足球入口 (/soccer)
  └─ 赛事列表（按联赛分组）
       └─ 单场详情 (/soccer/match/:matchId)
            ├─ 左栏：盘口市场区
            └─ 右栏：比赛信息面板 + 投注单
```

### 3.2 赛事列表页

**功能**：展示所有比赛，按联赛分组，每场显示核心盘口预览。

#### 3.2.1 左侧导航栏

| 区域 | 内容 |
|------|------|
| 页面标题 | 「足球」+ 地球图标 |
| 「全部赛事」按钮 | 显示总场次 + live 场次计数（红色） |
| 联赛按钮列表 | 每行：联赛名 + 国家（小字） + live 计数（红色，仅 > 0 时显示） + 总场次 |
| 「即将开赛」区块 | 展示前 3 场 live 比赛（红色脉动点 + 双方 shortName + 实时比分） |

> **已知问题**：「即将开赛」区块标题与实际展示内容不一致——标题为"即将开赛"但实际展示的是 live 比赛。

点击联赛按钮 → 筛选主区域仅显示该联赛比赛；点击「全部赛事」→ 恢复全部展示。

#### 3.2.2 比赛列表主区域

**按联赛分组**：每个联赛一组，组头显示联赛名 + 「N 场」。

**列标头行**（sm 以上可见）：

| 列 | 宽度 | 说明 |
|----|------|------|
| 时间 | w-12 | 比赛时间或状态 |
| 比赛 | flex-1 | 主队 vs 客队 |
| 1x2 | w-182px | 胜平负三列（sm+ 可见） |
| 总进球 | w-118px | O/U 2.5 两列（md+ 可见） |
| 亚盘 | w-138px | 亚洲让分盘首行两列（lg+ 可见） |
| 盘口 | w-16 | 「+N」盘口总数 |

**渐进式信息披露**：

| 断点 | 显示内容 |
|------|----------|
| 始终显示 | 时间/状态 + 队名 + 盘口数（"+N"） |
| sm+ (640px) | + 1x2 赔率（以 1/X/2 简写标注） |
| md+ (768px) | + O/U 2.5 两列（O 2.5 / U 2.5） |
| lg+ (1024px) | + 亚盘首行两列 |

**状态显示**：

| 状态 | 显示 |
|------|------|
| scheduled | 日期（小字）+ 时间（等宽字体） |
| live | 「LIVE」红色文字 + 比分（粗体等宽） |
| finished | 「FT」灰色文字 + 比分（灰色等宽） |

**盘口数计算**：`tabs.length × 8`（估算值），显示为 `+N` 格式，teal 绿色，hover 下划线。

点击任一行 → 跳转至 `/soccer/match/:matchId` 单场详情页。

### 3.3 单场详情页布局

**桌面端双栏布局**（无移动端适配）：

| 左栏（flex-1） | 右栏（w-380px, sticky） |
|----------------|------------------------|
| 面包屑导航（联赛名可点击筛选） | MatchInfoPanel |
| MatchHeader（比赛头部） | （阵容/H2H/统计 Tab） |
| Tab 栏（11 个标签页） | 投注单（始终显示，含空状态） |
| 盘口市场列表 | 我的投注（已结算投注记录） |

**面包屑导航**：格式为「足球 › 联赛名 › 比赛名」。联赛名为可点击链接，点击后跳转至赛事列表页并按该联赛筛选（URL 参数 `?league=leagueId`）。

### 3.4 三种赛事状态下的页面差异

| 状态 | MatchHeader | 右侧面板 | 盘口区 |
|------|-------------|----------|--------|
| **scheduled** | 即将开赛 badge + 日期时间 + 场地信息 | 倒计时 + 阵容图 + H2H | 正常可投注 |
| **live** | LIVE badge + 比分 + 当前分钟（脉动） + 场地信息 + 时间线高亮 | 事件时间线 + 统计 + 阵容 | 滚球盘口（部分暂停灰显） |
| **finished** | ENDED badge + 最终比分（灰色） + 场地信息 | 完整事件 + 统计 + H2H | 全部盘口显示结算结果（赢/输/void） |

### 3.5 投注单 UI/UX 规范

投注单位于右栏，排在 MatchInfoPanel 下方，始终显示（含空状态）。

#### 3.5.1 空状态

投注单无选项时显示标题「投注单」+ 居中提示文案「点击赔率按钮添加选项」。

#### 3.5.2 有选项时

| 区域 | 内容 |
|------|------|
| 标题行 | 「投注单」+ 绿色圆角数字 badge（选项数量） + 右侧「清空」按钮 |
| 选项卡片列表 | 每项包含：matchLabel（10px 灰色）+ marketTitle（12px）+ selection（12px teal 绿）+ odds（14px 粗体等宽）；hover 时右上角显示圆形 × 删除按钮 |
| 组合赔率（多选时） | 分隔线下方，左「组合赔率」右为 `odds1 × odds2 × ... × oddsN` 的乘积值 |
| 投注金额输入 | 标签「投注金额」，数字类型，placeholder "0.00"，后缀 "USDT" |
| 预计收益 | 左「预计收益」右为 `金额 × comboOdds` 实时计算值，teal 绿色 |
| 确认按钮 | 全宽「确认投注」按钮，金额为空或 ≤ 0 时禁用（灰色不可点击）；或投注单中包含暂停（suspended）盘口 |

#### 3.5.3 交互行为

- 点击盘口赔率按钮 → 选项加入投注单，按钮高亮
- 再次点击已选按钮 → 取消选择，选项从投注单移除
- 同一盘口只能选一个选项（新选同一盘口的不同选项会替换旧选项）
- 点击选项卡片的 × → 移除该项
- 点击「清空」→ 清除全部选项
- 金额变化 → 预计收益实时重算
- **已结束比赛禁止投注**：当比赛状态为 finished / abandoned / cancelled / corrected 时，点击赔率按钮无响应，不可新增投注项。投注单显示对应状态提示（如"比赛已结束"），隐藏金额输入与确认按钮

### 3.6 我的投注面板

位于右栏投注单下方，展示当前用户在该场比赛的已结算投注记录。

#### 3.6.1 面板结构

| 区域 | 内容 |
|------|------|
| 标题行 | 「我的投注」 |
| 汇总行 | 总盈亏金额（正值绿色 +X.XX，负值红色 -X.XX），单位 USDT |
| 投注记录列表 | 每条记录包含：比赛名、盘口名、选项、赔率、投注金额、结果 badge |

#### 3.6.2 结果展示

| 结果 | Badge 样式 | 金额显示 |
|------|-----------|----------|
| **win**（赢） | 绿色 badge「赢」 | 绿色 `+盈利金额`（= 投注额 × 赔率 − 投注额） |
| **loss**（输） | 红色 badge「输」 | 红色 `-投注金额` |
| **push**（退款） | 灰色 badge「退款」 | 灰色 `±0.00` |

## 第 4 章：UI 组件与市场类型规范

产品定义了 6 种市场 UI 类型，每种对应一个前端组件。

### 4.1 ButtonGroupMarket（按钮组）

**用途**：N 选 1 的简单选择，如胜平负、是/否。

**数据结构**：
```
{
  type: 'buttonGroup'
  title: string
  options: { label: string, odds: number }[]
}
```

**交互行为**：
- 点击任一按钮 → 该选项加入投注单，按钮高亮
- 再次点击已选按钮 → 取消选择，从投注单移除
- 同一盘口同时只能选一个选项

**适用盘口示例**：胜平负、平局返还、双胜彩、两队都得分

### 4.2 OddsTableMarket（赔率表格）

**用途**：多行多列的结构化赔率展示，如大小球（多条线）、亚洲让分盘。

**数据结构**：
```
{
  type: 'oddsTable'
  title: string
  columns: string[]          // 列头，如 ['高于', '低于'] 或 [主队, 客队]
  rows: { line: string, odds: number[] }[]  // 每行一条盘口线
}
```

**交互行为**：
- 每个单元格（line + column 交叉点）是一个可选项
- 选项标识为 `{column} {line}`，如「高于 2.5」
- 点击单元格 → 加入投注单

**适用盘口示例**：合计 O/U、亚洲让分盘、角球总数、红黄牌总数

### 4.3 ScoreGridMarket（比分矩阵）

**用途**：在一个网格中展示所有可能比分及对应赔率，如正确比分。

**数据结构**：
```
{
  type: 'scoreGrid'
  title: string
  homeRange: number[]     // 主队进球范围，如 [0,1,2,3,4]
  awayRange: number[]     // 客队进球范围
  odds: Record<string, number>  // 键为 'H:A' 格式，如 '2:1'
}
```

**交互行为**：
- 仅赔率 > 0 的格子可点击
- 赔率为 0 或键不存在的格子显示为空占位
- 选项标识为比分字符串，如 `2:1`

**适用盘口示例**：正确进球（全场 0-4 × 0-4）、上半场正确进球（0-2 × 0-2）、下半场正确比分

### 4.4 PlayerListMarket（球员列表）

**用途**：按球员展示多档赔率，如进球者、助攻、射门。

**数据结构**：
```
{
  type: 'playerList'
  title: string
  tiers: string[]                          // 档位标签，如 ['1+','2+','3+']
  players: { name: string, odds: number[] }[]  // 每名球员每档一个赔率
}
```

**交互行为**：
- 单档（tiers.length === 1）时选项标识为球员名
- 多档时选项标识为 `{name} {tier}`
- odds === 0 的档位渲染为空位，不可点击
- 默认显示前 8 名球员，点击「展开」显示全部

**适用盘口示例**：任何时间进球队员（约 34-36 人单档）、球员射门（约 34-36 人 6 档）

### 4.5 ComboGridMarket（组合网格）

**用途**：两个维度的组合选择，如「谁赢 × 两队是否都进球」。

**数据结构**：
```
{
  type: 'comboGrid'
  title: string
  rowHeaders: string[]
  colHeaders: string[]
  cells: { label: string, odds: number }[]  // 按行主序铺平
}
```

**交互行为**：
- 若只有一列或首列为空串 → 按过滤 odds > 0 的网格按钮展示
- 否则按行列渲染表格
- odds === 0 的单元格视为空位

**适用盘口示例**：1x2 & 两队得分、半场/全场、1x2 & 合计、Multiscores

### 4.6 RangeButtonsMarket（区间按钮）

**用途**：从多个预定义区间中选择一个，如总进球数、多进球范围。

**数据结构**：
```
{
  type: 'rangeButtons'
  title: string
  options: { label: string, odds: number }[]
}
```

**交互行为**：
- 与 ButtonGroupMarket 交互一致
- 视觉上横向 flex-wrap 排列

**适用盘口示例**：总进球数（0-5+）、多进球（1-2 到 7+）、角球范围

#### 5.1.2 平局返还

| 字段 | 内容 |
|------|------|
| **盘口名称** | 平局返还 |
| **UI 类型** | ButtonGroup |
| **一句话解释** | 只有主胜和客胜两个选项，如果打平则投注作废退款 |

#### 5.1.3 双胜彩

| 字段 | 内容 |
|------|------|
| **盘口名称** | 双胜彩 |
| **UI 类型** | ButtonGroup |

## 第 10 章：边界条件与异常处理

### 10.1 赔率为 0 的处理

- **ScoreGridMarket**：odds 中不存在的键或值为 0 → 渲染为空格占位，不可点击
- **PlayerListMarket**：某档 odds === 0 → 该档位显示为空位，不可选择
- **ComboGridMarket**：label 为 `-` 且 odds === 0 → 空单元格
- **OddsTableMarket**：odds 为 0 的单元格显示 '—'，不可点击（待实现）

### 10.2 球员未上场

- 进球者/球员市场中，若球员**完全未上场**（未在首发或替补名单中出场）→ 投注 **void**
- 若球员在进球已发生后才上场 → 视为 runner，可能影响 Anytime Goalscorer 结算 [FR014]

### 10.3 比赛中断后的盘口状态迁移

```
open (可投注)
  → interrupted → suspended (暂停)
    → 48h 内恢复 → open (重新开放)
    → 48h 外未恢复 → void (全部作废)
  → abandoned → 已决定结果的市场 → settled；未决定的 → void [FR004]
```

### 10.4 投注单中的盘口被关闭

- 盘口从 open → suspended：投注单中对应项标灰，不可提交
- 赔率变化：提交时需校验赔率是否仍然有效
- 盘口从 open → void：投注单中对应项自动移除

### 10.5 同一盘口跨 Tab 重复

同一盘口（如「胜平负」）在多个 Tab 中出现时：
- 数据源为同一个 Market 对象引用
- 选择状态全局同步——在 Tab A 选中后切换到 Tab B 仍显示选中
- 投注单中不会出现同一盘口的重复项

### 10.6 半场与全场结算时序

1. **上半场结束** → 所有上半场类盘口可结算（1x2、正确比分、大小球、角球等）
2. **全场结束（常规时间含补时）** → 所有全场类盘口结算
3. **加时赛（若有）** → 仅影响标注「含加时」的球员盘口 [FR016]
4. **点球大战** → 不影响本文档定义的任何盘口（未包含加时赛/点球大战专属市场）

### 10.7 加时赛对「含加时」盘口的影响

本文档中标注「包含加时」的盘口有：
- 球员助攻 (包含加时)
- 球员被罚牌（含加时）
- 球员射门 (包含加时)

**规则** [FR016]：
- 若比赛**有加时赛** → 加时赛中的数据也计入结算
- 若比赛**无加时赛** → 按常规时间结果结算（与不含加时的盘口相同）

### 10.8 投注单的组合赔率计算

- 单注赔率 = 所选选项的 odds 值
- 多选组合赔率 = 各选项 odds 相乘：`comboOdds = odds1 × odds2 × ... × oddsN`
- 预计收益 = 投注金额 × comboOdds
- 任一子选项 void → 该项从组合中移除，赔率重算；若全部 void → 退款

### 10.9 乌龙球结算差异汇总

| 盘口 | 乌龙球处理 | 规则 |
|------|-----------|------|
| 任何时间进球队员 | **忽略**，不计入该球员的进球 | FR013 |
| Player to score (incl. overtime) | **忽略** | FR013 |
| Next Goalscorer | **独立结果**，乌龙球单独列出 | FR015 |
| 1st 进球队员 | 遵循 Next Goalscorer 规则（待确认） | FR015 |
| 正确比分/比分类 | 乌龙球**计入比分**（进球归对方） | 比分结算通则 |
