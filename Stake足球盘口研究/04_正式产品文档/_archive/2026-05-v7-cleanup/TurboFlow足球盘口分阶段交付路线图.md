## 1. 文档定位

本文档是 TurboFlow 足球盘口产品的**分阶段交付路线图**。以 PRD v3（`TurboFlow足球盘口产品需求文档_v3.md`）定义的全量 100+ 盘口为基础，先按**玩法逻辑族**给所有盘口分类，再按族的复杂度和数据依赖递进排入 4 个交付阶段。

**本文档不替代 PRD**——盘口的详细定义（UI 类型、胜负判定、结算规则、字段配置等）仍以 PRD v3 为准。本文档只回答：**什么时候做什么、为什么这样排**。

---

## 2. 阶段总览

| 阶段 | 定位 | 盘口数 | 核心数据管道 | 状态 |
|------|------|--------|-------------|------|
| **Phase 0** | 产品定义 + 前端 Mockup | 100+（全量定义） | mock 数据 | 已完成 |
| **Phase 1** | 基础玩法族（全场版） | ~35 | 常规时间最终比分 | 待开发 |
| **Phase 2** | 半场变种 + 统计事件族 | ~55 | + 半场比分 + 角球/罚牌事件流 | 待开发 |
| **Phase 3** | 球员级深市场 + 组合投注 | ~15 + SGM | + 球员事件流 + 组合引擎 | 待开发 |

## 3. 玩法逻辑族分类

PRD v3 定义的 100+ 盘口，按核心判定逻辑归纳为 **10 个玩法族 + 1 个平台能力层**。同一族内的盘口共享相同的判定机制，不同盘口只是在时间口径（全场/半场）、数据源（进球/角球/罚牌）、范围（全队/单队）上做变种。

### 3.1 族 A：赛果族（N 选 1 赛果判定）

**核心机制**：常规时间结束后，判定比赛结果属于哪个选项（主胜/平局/客胜，或其合并）。

| 盘口 | PRD 章节 | 变种维度 | 选项数 |
|------|----------|---------|--------|
| 胜平负 (1x2) | 5.1.1 | 基准 | 3 |
| 平局返还 (Draw No Bet) | 5.1.2 | 平局 → void | 2 |
| 双胜彩 (Double Chance) | 5.1.3 | 两项合并 | 3 |
| 上半场 1x2 | halves #1 | 半场时间口径 | 3 |
| 上半场平局返还 | halves #2 | 半场 + void | 2 |
| 上半场双胜彩 | halves #3 | 半场 + 合并 | 3 |
| 下半场 1x2 | halves 下半场组 | 半场时间口径 | 3 |
| 下半场平局返还 | halves 下半场组 | 半场 + void | 2 |
| 下半场双胜彩 | halves 下半场组 | 半场 + 合并 | 3 |
| 10 分钟 1x2 | 5.11/minutes #1 | 时间窗口(10分钟) | 3 |

**判定逻辑统一公式**：在指定时间口径内，比较双方进球数 → 确定赢/平/输 → 匹配到对应选项。

---

### 3.2 族 B：大小球族（与盘口线比较）

**核心机制**：某个统计数值（进球/角球/罚牌）与预设的盘口线比较，判定高于还是低于。

| 盘口 | PRD 章节 | 数据源 | 盘口线范围 |
|------|----------|--------|-----------|
| 合计 O/U | 5.1.4 | 全场总进球 | 1.25~3.25 |
| 主队合计 / 客队合计 | 5.2.1 | 单队进球 | 0.5~4.5 |
| 亚洲总进球 O/U | asian #2 | 全场总进球 | 四分之一球线 |
| 上半场总计 | asian #4 | 半场总进球 | 6 条线 |
| 下半场总数 | asian #6 | 半场总进球 | 6 条线 |
| 上半场主/客队合计 | halves #14 | 半场单队进球 | — |
| 角球总数 O/U | corners #1 | 全场角球 | 7.5~11.5 |
| 上半场角球总数 | corners #7 | 半场角球 | 3.5~5.5 |
| 红黄牌总数 O/U | cards #1 | 全场罚牌 | 3.5/4.5/5.5 |
| 上半场红黄牌总数 | cards #3 | 半场罚牌 | 1.5 |
| 两个半场高于/低于 1.5 | 5.2.13 | 跨半场 | 1.5 |

**判定逻辑统一公式**：统计值 > 线 → 高于赢；< 线 → 低于赢；= 整数线 → push（退款）；四分之一球线 → 半注拆分。

### 3.3 族 C：让分盘族（虚拟加减球后比较）

**核心机制**：给一方虚拟加或减若干球，再判定调整后的赛果。

| 盘口 | PRD 章节 | 让球方式 | 结果选项 |
|------|----------|---------|---------|
| 亚洲让分盘 | 5.1.5 | 亚洲盘（二项） | 主/客 |
| 上半场让球 | asian #3 | 半场亚洲盘 | 主/客 |
| 下半场盘口 | asian #5 | 半场亚洲盘 | 主/客 |
| 让分 0:1 欧洲让球 | 5.2.20 | 欧洲盘（三项） | 主/平/客 |
| 上半场让球 0:1/0:2/1:0/2:0 | halves #10 | 半场欧洲盘 | 主/平/客 |
| 下半场让球 0:1/0:2/1:0/2:0 | halves 下半场组 | 半场欧洲盘 | 主/平/客 |
| 角球盘口 | corners #5 | 角球亚洲让分 | 主/客 |
| 上半场角球盘口 | corners #9 | 半场角球让分 | 主/客 |

**判定逻辑统一公式**：实际值 + 虚拟让球 → 调整后数值 → 按赛果/亚盘规则判定。

### 3.4 族 D：是/否族（二元条件判定）

**核心机制**：某个条件成立 → "是"赢，否则 → "否"赢。

| 盘口 | PRD 章节 | 判定条件 |
|------|----------|---------|
| 两队都得分 (BTTS) | 5.1.6 | 双方各 ≥ 1 球 |
| 上半场两队得分 | halves #8 | 半场双方各 ≥ 1 球 |
| 下半场两队进球 | halves 下半场组 | 半场双方各 ≥ 1 球 |
| 主/客队不失球 | 5.2.7 | 对方 0 球 |
| 主/客队不丢球获胜 | 5.2.17 | 赢 + 对方 0 球 |
| 主/客队两个半场得分 | 5.2.14 | 上下半场各 ≥ 1 球 |

| 主/客队赢两半场 | 5.2.19 | 两个半场均领先 |

**判定逻辑统一公式**：布尔表达式 → true = "是"赢，false = "否"赢。

### 3.6 族 F：组合族（两维交叉同时命中）

**核心机制**：两个独立维度的判定结果交叉组合，必须同时命中才赢。

| 盘口 | PRD 章节 | 维度 1 | 维度 2 |
|------|----------|--------|--------|
| 1x2 & 两队得分 | 5.1.7 | 赛果(A) | BTTS(D) |
| 半场/全场 | 5.1.10 | 半场赛果(A) | 全场赛果(A) |
| 1x2 & 合计 | 5.3.1 | 赛果(A) | 大小球(B) |
| 双胜彩 & 合计 | goals Tab | 双胜彩(A) | 大小球(B) |
| 合计 & 两队得分 | 5.3.2 | 大小球(B) | BTTS(D) |
| 上/下半场两队得分 | 5.3.3 | 上半场BTTS(D) | 下半场BTTS(D) |
| 1st 进球 & 1x2 | 5.3.5 | 先进球方(H) | 赛果(A) |
| 上半场 1x2 & 两队都进球 | halves #4 | 半场赛果(A) | 半场BTTS(D) |
| 上半场 1x2 & 合计 | halves #5 | 半场赛果(A) | 半场大小球(B) |

**判定逻辑统一公式**：维度 1 结果 × 维度 2 结果 → 命中交叉格 → 赢。

### 3.9 族 I：进球者族（球员级进球判定）

**核心机制**：预测某位球员是否进球（含 runner/乌龙球特殊规则）。

| 盘口 | PRD 章节 | 判定 | 特殊规则 |
|------|----------|------|---------|
| 任何时间进球队员 | 5.1.11 | 该球员 ≥ 1 球 | 乌龙球忽略 [FR013]；runner [FR014] |
| 1st 进球队员 | 5.2.21 | 打入比赛首球 | 乌龙球独立结果 [FR015] |
| 最后进球队员 | 5.2.22 | 打入比赛末球 | 同 1st |

**共性**：球员未上场 → void；需要球员级事件流。

### 3.10 族 J：球员统计族（球员级数据达标判定）

**核心机制**：某球员的某项统计数据是否达到 N 档阈值。

| 盘口 | PRD 章节 | 统计项 | 档位 |
|------|----------|--------|------|
| 球员助攻 (含加时) | players #2 | 助攻数 | 1+, 2+ |
| 球员被罚牌 (含加时) | players #3 | 罚牌数 | 1+ |
| 球员射中次数 | players #4 | 射正数 | 1+~5+ |
| 球员射门 (含加时) | players #5 | 射门数 | 1+~6+ |

**共性**：标注「含加时」者，无加时赛按常规时间结算 [FR016]；需要球员级统计 feed。

### 3.11 族 K：时间区间族（事件发生时段判定）

**核心机制**：某个事件（如首球）发生在哪个预定义时间窗口内。

| 盘口 | PRD 章节 | 时间切片 |
|------|----------|---------|
| 1st 进球（10 分钟） | 5.3.6 | 1-10 / 11-20 / ... / 81-90 / 无进球 |
| 1st 进球（15 分钟） | 5.3.6 | 1-15 / 16-30 / ... / 76-90 / 无进球 |

**特殊规则**：31-45 和 76-90 时间段包含补时 [FR021]。

---

### 3.12 能力层 Z：同场赛复式投注 (SGM / Bet Builder)

**不是一个"玩法"，而是一个平台能力层**——将上述任意盘口的选项组合为一注，赔率相乘。

- PRD 章节：Tab 2 bet-builder（~96 个盘口的 SGM 版本）
- 组合规则：赔率 = odds1 × odds2 × ... × oddsN
- void 处理：任一子选项 void → 从组合中移除并重算；全部 void → 退款
- 前提：上述 A-K 族的盘口需先独立上线，SGM 在其基础上叠加

## 8. 风险与注意事项

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 数据源质量 | 第三方 feed 延迟、缺失或错误可能导致结算问题 | 多源校验 + 人工兜底 |
| 亚洲让分盘规则未完全确认 | PRD 中标注部分规则为 unknown | Phase 1 上线前需补全规则确认 |
| 半场结算时序 | 半场结束的精确时间判定依赖数据源 | 与数据方确认半场终了推送逻辑 |
| 球员数据完整性 | 进球者/助攻等球员级数据可能缺失 | Phase 3 前充分评估数据源覆盖率 |
| SGM 关联性 | 同场赛组合投注需处理盘口间的统计关联 | 引入关联性模型，避免简单赔率相乘导致定价偏差 |
